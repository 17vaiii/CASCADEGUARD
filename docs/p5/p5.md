## 2. Design decisions

1. **Second resource (documented assumption).** P1's corridor is single-source, with hydro on the
   slack bus, so P5 adds an **equivalent Karnataka state-grid tie at NELAMANGALA**: a
   controllable active-power import, limit 200 MW, not grid-forming. The Sharavathi slack is the
   Linganamakki hydro plant. Base dispatch puts hydro first, up to capacity and 85 % of the
   average daily energy budget, and the tie covers the rest. In summer that means about 200 MW of
   import, because the reservoir is low.
2. **Reactive schedule.** With high import the long line runs light and P1's always-on capacitors
   push voltages to 1.10 pu. The pre-contingency state switches banks out until it is ≤ 1.05 pu.
   Plans may add capacitor switch-outs as recorded actions.
3. **H2/H3 bounds** come from P1's `grid.hydro.dispatch_hydro`. Ramp = rate × 10-minute window.
   The upward bound also keeps the day's energy within budget if the raised output is held for a
   2-hour emergency and then returned to schedule. No ramp-up is allowed below the 30 % reservoir
   floor.
4. **Closed-loop verification.** Every plan is re-simulated with P1's `simulate_cascade`. It is
   *verified* only if the intended controlled shed is the **only** load lost: no further trips, no
   islanded load, no UFLS, voltage within 0.92–1.08 pu, hydro within bounds, and every line below
   100 %. A generation deficit beyond the hydro bound triggers modelled uncontrolled UFLS
   (deficit × 1.25, at the load end).
5. **Optimizer.** AC finite-difference sensitivities (one power flow per control) feed a SCIP MILP
   through OR-Tools. It minimises shed (1000/MW), tie redispatch (15/MW), switching (300) and
   60 per action, subject to every line ≤ 96 % and hydro within bounds. Switch candidates that
   would island load are excluded. If verification fails, the problem is re-linearised with a
   target 3 % tighter (up to 3 iterations), then falls back to greedy, then to the best unverified
   plan (flagged).
6. **Retrieval.** Physics embedding (post-contingency loadings, trips, season, deficit) or P3 GNN
   128-d embedding; exact cosine search locally; Qdrant upsert supported. Warm start tries
   precedent actions directly (one re-simulation); otherwise it seeds the closed loop.
7. **Copilot.** Seven project-authored corpus documents, each marked illustrative or
   project-only; local hybrid TF-IDF retrieval. The brief uses only computed facts. With
   credentials it calls Claude `claude-opus-5-5` (effort medium, server-side refusal fallback
   `fallbacks="default"`). The output must pass citation, number-grounding and over-claim checks,
   or the extractive brief is used.
8. **Dashboard** calls the Python modules directly and reads P4/P5 artifacts; missing artifacts
   degrade to an instruction message.

## 4. Verified results (2026-11-05, seed 42, 471 events, 95 s on CPU)

Event set per season: 76 N-1, 60 sampled N-2, loss of the state-grid tie, and 20 tie loss + N-1.

| Season | Base dispatch | Events | Lose load with no action | No action (mean lost) | Greedy | **Optimizer** | Verified (opt / greedy) |
|---|---|---|---|---|---|---|---|
| Monsoon | hydro 315 MW, import 0 | 157 | 0 | — | — | — | — |
| Post-monsoon | hydro 354 MW, import 0 | 157 | 53 | 100 % | 0.83 % | **0.71 %** | 100 % / 100 % |
| Summer | hydro 218 MW, import 200 MW | 157 | 21 | 42.9 % | 29.76 % | **29.75 %** | 100 % / 100 % |

- Post-monsoon: 50 events are fixed by one action, raising import (mean +41 MW) so hydro backs
  down and the surviving parallel circuit stays below its rating: a 100 % blackout becomes 0 %.
  3 tie-loss + N-1 events need a controlled 43 MW shed at PEENYA plus a capacitor switch-out
  (12.5 % instead of 100 %). Optimizer vs greedy, over 53 events both verified: mean actions 1.06
  vs 1.11, mean shed 2.4 vs 2.9 MW.
- Summer tie loss: hydro ramps the full 80 MW allowed by the ramp window and reservoir budget,
  plus a controlled 123 MW shed at PEENYA: 29.7 % lost instead of 42.9 % from automatic UFLS.
  There were 21 hydro ramp-up plans and no hydro-bound violations.
- Optimizer solve time: 17–27 ms per MILP. End to end, including sensitivities and verification:
  0.66 s (post-monsoon) to 1.8 s (summer) per event.
- **Honest comparison:** on this radial corridor most events have one binding constraint, so
  greedy is near-optimal and the MILP's gain is small. The MILP's value is a guaranteed minimum
  over several simultaneous constraints and the hydro/tie bounds.
- One unmitigable class, both circuits of section 0 (N-2 islands all load from the only source),
  is correctly reported as *unverified, no remedial action exists* rather than as a fake fix.

**R8 retrieval + P5-5 warm start** (74 mitigated cases: 52 library, 22 queries, k = 3):
precision@3 of action type 0.97 physics and 0.98 GNN embedding (precision@1 1.00 and 0.95), against a
majority-class baseline of 0.68. Warm start: every query was solved by applying
the precedent's actions directly (verified in one re-simulation), **5.3× faster** (4.9–7.9× across runs) than cold
optimisation (0.21 s vs 1.10 s), with the same pass rate (100 %), load loss (9.46 vs 9.47 %) and
action count (1.0).

**Theft-aware mitigation** (P4 link; monsoon, hidden load = 3 × simulated NTL = 12.5 MW true,
12.4 MW estimated by P4): 22 N-1 events cascade on the true state. Plans made on the SCADA
(metered-only) view said "no action needed" for all 22, giving 100 % loss on the true system.
Plans made on P4's theft-aware view were **verified on the true state 22 / 22, with 0 % loss.**

**R11 copilot:** extractive briefs pass the citation and number-grounding checks. The LLM path is
tested with a fake client: request shape (`claude-opus-5-5`, `fallbacks="default"`, the
`server-side-fallback-2026-07-01` beta, no sampling parameters), refusal fallback, and the
grounding-failure fallback. No live LLM call was made in this environment (no credentials).

**Dashboard:** a real browser (Playwright + Chromium) walked the demo, including every role: 0 console
errors, 0 page errors. Report, screenshots and `demo_walkthrough.webm` are in `demo_media/`.

## 6. How to run (repository root)

```bash
pip install -r requirements-p5.txt                                   # ortools, streamlit, plotly
PYTHONPATH=src python -m cascadeguard.theft.pipeline                 # P4 artifacts (theft view, T9 hidden load)
PYTHONPATH=src python -m cascadeguard.mitigation.experiment          # P5 metrics + case library (~2 min)
PYTHONPATH=src streamlit run src/cascadeguard/dashboard/app.py       # dashboard on :8501
PYTHONPATH=src python -m pytest tests -q -W ignore                   # 87 tests
PYTHONPATH=src python -m cascadeguard.retrieval.load_qdrant --url http://localhost:6333   # needs Qdrant
PYTHONPATH=src python -m cascadeguard.dashboard.browser_walkthrough  # needs playwright + chromium
docker compose --profile local-platform up --build -d qdrant mlflow api dashboard
PYTHONPATH=src python -m uvicorn cascadeguard.api.main:app --port 8000
```
PowerShell: `$env:PYTHONPATH="src"; .\.venv\Scripts\python.exe -m streamlit run src/cascadeguard/dashboard/app.py`.
LLM briefs: set `ANTHROPIC_API_KEY` (or run `ant auth login` and set `CASCADEGUARD_COPILOT_LLM=1`).

`POST /api/mitigate` body:
`{"snapshot": {"season": "post_monsoon", "lines": [0], "tie_loss": false, "theft_aware": false}, "options": {"brief": true}}`.
Line indices: section *s* has circuits `2s` (A) and `2s+1` (B), for 38 sections from Sharavathi
(s = 0) to Peenya (s = 37).

Outputs: `data/models/mitigation/mitigation_metrics.json`, `data/models/mitigation/cascade_case_library.pkl`,
`data/processed/mitigation/{mitigation_results,warm_start,theft_aware_mitigation}.parquet`.
